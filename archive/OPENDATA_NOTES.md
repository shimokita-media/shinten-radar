# IFAS 営業許可オープンデータ 実データ調査メモ

2026-09-03 に実データ（2026年07月末現在版）を取得して確認した内容。すべて実測。

## 取得元

**ドメインが移転しています。** `ifas.mhlw.go.jp` は JS リダイレクトのみを返す静的ページで、
現行は **`i2fas.mhlw.go.jp`**。

ダウンロードURLは自治体コードだけで組み立て可能。**セッション・Cookie・Referer は不要**で、
素の `curl` / `urllib` で 200 + `Content-Disposition: attachment` が返る（実測確認済み）。

```
https://i2fas.mhlw.go.jp/faspub/page/opendatadownload.jsp?param=<自治体コード>_food_business_all.csv
```

画面上は非同期POSTを経由するように見えるが、生成される最終URLは上記の固定形式。
`fetch_opendata.py` で自動取得できるので、手動手順は不要。

更新頻度は月次（前月末時点のスナップショット）。

## ファイル分割

東京都エリアは保健所設置主体ごとに **26ファイル**。

| 区分 | コード | 備考 |
|---|---|---|
| 特別区23区 | 13101〜13123 | 各区が個別ファイル |
| 八王子市 | 13201 | 個別 |
| 町田市 | 13209 | 個別 |
| 東京都 | 13000 | **多摩地域（八王子・町田を除く）＋島しょ**のみ。23区を含まない |

実測行数（2026年07月末版）: 26ファイル合計 **63,198行**、うち23区のみ **50,576行**。

## 形式

- 文字コード **UTF-8（BOM付き）** — CP932 ではない。`encoding="utf-8-sig"` で開くこと
- 改行 **CRLF**
- 25列。**26ファイルすべてでヘッダは完全に同一**（実測でシグネチャ1種類）

## 実装上の落とし穴（実データで確認したもの）

1. **`自治体コード` は `"013113"` と6桁ゼロ埋め。** URL/画面で使う5桁 `13113` と一致しない。
2. **`D列 市区町村名` は管轄自治体の所在地であって施設住所ではない。** 施設住所は I 列。
   **D列はファイル内で完全に定数**（実測: 26ファイルすべてユニーク値1個）。
   最悪なのが `13000`（東京都 = 多摩地域＋島しょ）で、**全9,964行のD列が `新宿区`**。
   実際の施設は武蔵野市などにある（I列: `東京都武蔵野市吉祥寺本町1-7-1`）。
   都庁所在地が入っているだけ。D列で区を判定すると多摩の1万件が新宿区に化ける。
3. **`営業の種類` に全角丸数字の接頭辞が付く**（`① 飲食店営業`）。
   さらに許可業種と届出業種で番号体系が別なので、`⑪` が `百貨店、総合スーパー` と
   `菓子製造業` の両方に存在する。**丸数字をキーに使ってはいけない。**
4. **日付・緯度経度はクォートなし**、日付書式は `yyyy/MM/dd`。
5. **`備考` は全63,198行で完全に空。** 中身のある列ではない。
6. **日付に異常値が混ざる。** `許可年月日` に `1021` 年のレコードが1件存在（2021のtypoと思われる）。
   年でフィルタするなら下限チェックが要る。
7. **母集団バイアス。** 掲載対象は「IFASで電子申請され、かつ申請者がオープンデータ掲載に
   同意したもの」に限られる。その保健所管内の全店舗ではない。

`申請区分` の内訳（全63,198行）:

| 申請区分 | 件数 |
|---|---|
| 届出 | 49,946 |
| 許可 | 12,938 |
| 届出(廃業) | 215 |
| 許可(廃業) | 99 |

許可年月日が完全に空。** つまり日付ベースの新店検知が効くのは全体の約 20.6% に限られる。
