# 新店レーダー

世田谷区の営業許可オープンデータから、下北沢エリア（北沢・代沢・代田・大原・羽根木）の
新店候補を毎月抽出するツール。抽出結果をもとに実際に店へ足を運んで取材する前提の「候補リスト」。

## セットアップ

```bash
pip install requests
```

pandas は不要（標準ライブラリの csv で読んでいる）。

## 使い方

### 新店を抽出する

```bash
python shinten_radar.py 8 5 8 6 8 7          # 令和8年5月・6月・7月分
python shinten_radar.py --last 3             # 直近3ヶ月分
python shinten_radar.py --last 1 --notify    # 抽出してLINE通知（初出のみ）
```

引数は `令和年 月` のペアの繰り返し。オプション:

| オプション | 意味 |
|---|---|
| `--last N` | 直近Nヶ月を自動で対象にする（当月は未公開なので含まない） |
| `--refresh` | キャッシュを無視して再ダウンロード |
| `--notify` | 初出の新店候補をLINEに送る（`.env` が必要） |
| `--all-areas` | エリア絞り込みなし。世田谷区全域 |

出力は `out/` に3種類。

- `shinten_YYYYMMDD.md` — 取材メモ用。**個店の新店候補 / チェーンの新店候補 / 更新とみられる** の3節に分かれる
- `shinten_YYYYMMDD.csv` — その回の抽出結果
- `shinten_all.csv` — 累積（地図生成の入力）

### 地図を作る

```bash
python build_map.py
```

`out/shinten_all.csv` と `out/heiten_*.csv` を読み、住所をジオコーディングして
`out/map.html` を書き出す。ブラウザで開くだけの1ファイル完結。

配色は黄と黒。ピンは色だけでなく**形**でも見分けられるようにしてある。

| 見た目 | 意味 |
|---|---|
| 黄の塗り＋黒のふち | 新店 |
| 黒の塗り＋黄のふち | チェーン |
| 中空＋黒の**破線** | 閉店の可能性（＝台帳から消えた） |

塗り＝台帳にある、破線＝消えた、という対応。上部のチップで表示/非表示を切り替えられる。

ピンをタップすると**いつからやっている店か**が出る。

- 新店　　… `オープン 2026-07-17 以降`
- 閉店候補 … `オープン 2020-06-26 以降` ＋ `閉店 2026-06-30 までに`
- 初回許可日が取れない行は `不明` と出す

オープン日は台帳の初回許可日（無ければ許可開始日）。いずれも**下限**なので「以降」と書く。
下のバー（広い画面では右のサイドバー）が一覧で、行をタップすると地図がその店に飛ぶ。
スマホ表示対応。

地図の下地は脱色して紙色に寄せてある。街路名を読めるまま残しつつ、ピンだけが立つようにするため。
色を変えるときは `build_map.py` の `KINDS` と、HTML内の `:root` のCSS変数を見る。

書体は見出し・本文とも Zen Kaku Gothic New（見出しは900）。台帳の日付だけ DotGothic16。
**ドット書体で日本語を組まないこと。** 漢字が点に潰れて読めなくなる。数字専用と考える。
見出しにもっと癖を出したいときは、HTML内の `<link>` に family を足したうえで
`--disp` を `"Zen Maru Gothic"`（丸ゴシック）などに差し替える。

ジオコーディングは国土地理院の住所検索APIを使い、失敗時のみ Nominatim にフォールバックする。
結果は `data/geocache.json` にキャッシュするので、2回目以降はAPIを叩かない。

### 閉店の可能性を調べる

方法が2つある。**普段は `--expired` を使う。**

```bash
python heiten_radar.py --expired          # 満了追跡（版が1つでも使える／毎月動く）
python heiten_radar.py --expired --ahead 6  # 「もうすぐ満了」の窓を6ヶ月に広げる
```

#### 満了追跡（--expired）のしくみ

全許可施設一覧には**満了切れの施設が1件も残っていない**。更新しなければ台帳から消える運用。
一方、更新した店は翌月の新規許可施設一覧に「1日開始」で再登場する。

そこで **満了日を過ぎたのに新規許可一覧へ戻ってこない店 = 閉店の可能性** として拾う。
令和8年6月30日満了の11軒で検証したところ、8軒が更新として再登場し、3軒が消えていた。

判定は許可単位ではなく**店単位**。1軒が飲食店営業と菓子製造業を別々に持つことがあり、
有効な許可が1つでも残っていれば営業中とみなして候補から外す。

`out/shinten_all.csv` があれば、**同じ住所にできた新店（跡地）**も併記する。

出力は4つに分かれる。

| 区分 | 意味 |
|---|---|
| 閉店の可能性 | 満了後、更新一覧に戻ってこない。**要現地確認** |
| Nヶ月以内に満了（見張り） | これから満了を迎える店。更新しなければ次の候補 |
| 判定保留 | 更新が載るはずの月の一覧がまだ未公開 |
| 更新を確認できた | 再登場した。営業中とみてよい |

区のサイトは新規許可一覧も直近数ヶ月分しか置いていない（4月分は既に404）。
古い月は判定保留になるので、`data/shinki/` のキャッシュを消さないこと。

#### 版間差分（引数なし）

```bash
python heiten_radar.py --fetch 8 3 31   # 全許可施設一覧の版を masters/ に保存
python heiten_radar.py                  # masters/ の最新2版を突合
```

**制約**：区のサイトには全許可施設一覧の最新版しか置かれていない（過去版は404）。
突合には2版必要なので、更新のたび（4月20日ごろ／10月15日ごろ）に `--fetch` して版を貯めていく。
現在 `masters/` にあるのは令和8年3月31日版のみ。次は令和8年10月15日ごろの版を取ること。

どちらの出力も「閉店した店」ではなく **「許可台帳の動きから推測した候補」**。
更新手続き中・更新漏れ・表記変更でも消えて見えるので、必ず現地確認する。

### 開店・閉店の年表を作る

```bash
python timeline.py
```

`out/shinten_all.csv` と `out/heiten_*.csv` を突き合わせ、月ごとに並べた
`out/timeline_<日付>.md` を書き出す。

**日付はすべて推測。** 許可データからわかるのは許可の日付だけなので、各項目に根拠と確度を併記する。

| | 言えること |
|---|---|
| オープン | 許可開始日が**下限**。飲食店は許可なしに営業できないので「この日以降」まで |
| 閉店 | 更新しなかったので許可満了日**まで**には閉じている（**上限**）。下限は出せない |
| 営業年数 | 台帳の初回許可日から。**下限**として扱う |

許可からオープンまでのラグは店によってバラバラなので、**下限表現のまま踏み込まない**こと。
「◯日ごろオープン」と書き換えないこと。

#### 「跡地」は方書まで一致したときだけ

同じ番地に別のビルが建っていたり、同じビルの別の階だったりする。実例：

| 閉店した店 | 同じ番地の新店 | 判定 |
|---|---|---|
| ソウルポチャ（芳澤ビル1階） | 夢吟坊 下北沢店（芳澤ビル1F） | ✅ 跡地 |
| 千禧茶（八千代ビル101） | TeNMi（小林ビル2階） | ❌ 別のビル |
| room310（sansato3F） | sansato（sansato1F） | ❌ 別の階 |
| 大浪漫商店（BONUS TRACK SOHO5） | ADDA（ボーナストラックsoho4） | ❌ 隣の区画 |

判定は `shinten_radar.same_unit()`。`1階`と`1F`、`B1`と`地下1階`を同じ値に正規化してから比べる。
番地しか一致しないものを「跡地」と書かないこと。

#### 初回許可日の性格

エリア923軒のうち、**132軒は1962〜2015年の実際の初回許可日**が入っている（最古は昭和37年）。
残り791軒は現在の許可がそのまま初回として記録されている。
営業者や屋号が変わると記録が新しく始まるので、**営業年数は下限**。

### チェーン店リスト

`chains.txt` を編集する。1行1キーワード、`#` はコメント。
屋号にそのキーワードが含まれたら「チェーン」に分類される（**除外ではなく別枠に分ける**）。
全角/半角の揺れは自動で吸収するので、見たままを書けばよい。

### 公開する

```bash
python build_map.py --public --base-url "https://USER.github.io/shinten-radar"
```

`docs/index.html` と `docs/ogp.png`（SNSサムネイル）を書き出す。GitHub Pages で配信する。
手順は `PUBLISH.md`。

**公開版には「閉店の可能性」を含めない**（`--public` が自動で除外する）。
台帳の動きからの推測なので、営業中の店を閉店扱いすると実害が出る。裏が取れた店だけ記事にする。

データは世田谷区の **CC BY 4.0**。地図フッターの出典表示を消さないこと。

### 月次の自動実行

`SETUP_SCHEDULER.md` を参照。Windows タスクスケジューラで毎月16日に `run_monthly.bat` を回す。

## データについて

### 新規許可施設一覧

- `https://www.city.setagaya.lg.jp/documents/3246/shinkir{和暦YYMMDD}.csv`
- ファイル名はその月の**末日**で決まる（令和8年7月分 → `shinkir080731.csv`）
- 毎月15日ごろ公開
- **文字コードは UTF-8（BOM付き）**。Shift-JISではない
- 列: `No., 施設所在地, 施設方書, 施設屋号, 営業者名, 営業所電話番号, 許可番号, 業種, 初回許可日, 許可開始日, 許可満了日`
- 1ヶ月あたり世田谷区全体で100〜120行。うち下北沢エリアは15〜20行

### 全許可施設一覧

- `https://www.city.setagaya.lg.jp/documents/3246/zenkenr{和暦YYMMDD}.csv`
- **文字コードは cp932（Shift-JIS）**。新規許可一覧とは違うので注意
- 約7400行。最新版のみ公開

### 新店と更新の見分け方

`許可開始日` が**月の1日**の行は更新許可の可能性が高いので「更新とみられる」に分ける。
根拠は、更新許可の開始日が前許可の満了翌日になり、満了日が月末に寄るため。
実データ（令和8年7月分99行）でも48行が1日開始に集中しており、
その多くは許可期間が「6年ちょうど−1日」で終わる＝更新のパターンだった。

**注意**：`初回許可日` 列は新規許可一覧では常に `許可開始日` と同じ値が入っており、
新店/更新の判別には使えない。1日開始の店が新店であることもあるので、最終判断は現地で。

## 絶対に守ること

1. **業態を推測で埋めない。** 許可データには屋号・住所・許可日・業種区分しかない。
   「ラーメン店」「居酒屋」といったジャンルはデータに存在しない。出力に業態を書かない。
2. **食べログ・Instagram をスクレイピングしない。** 裏取り支援は検索URLの生成までに留める。
3. **廃業は反映されないことを出力に明記する。** 許可済み＝営業中ではない。
4. **屋号が空の行は落とす。** 自宅営業の個人情報配慮。この除外を精度向上の名目で外さない。
5. **出典表示を出力に含める。** 出典：「新規許可施設一覧」（世田谷区）

## ファイル構成

```
shinten_radar.py        新店抽出（メイン）
heiten_radar.py         閉店の抽出（--expired が主）
timeline.py             開店・閉店の年表
build_map.py            地図HTML生成
make_ogp.py             SNS用サムネイル画像
chains.txt              チェーン店キーワード
docs/                   公開版（GitHub Pages で配信する。gitに載る唯一の出力）
run_monthly.bat         月次実行バッチ
.env                    LINEのトークン（gitignore済み。.env.example をコピーして作る）
data/shinki/            新規許可一覧のキャッシュ
data/geocache.json      ジオコーディング結果のキャッシュ
masters/                全許可施設一覧のアーカイブ
state/seen.json         初出判定用の状態
out/                    出力

archive/                旧版（厚労省 食品衛生申請等システム）。現行とは無関係。参照用
```
